# Как помочь

Спасибо, что заглянули. Проект небольшой, и самая ценная помощь — вычитать
перевод и сообщить о неточностях.

## Сообщить о проблеме с переводом

Откройте [issue](../../issues/new?template=translation.yml) и укажите:

1. **Где видно** — раздел приложения (например, «Настройки → Общие» или
   «боковая панель → Файлы»).
2. **Что показано сейчас** — точный текст.
3. **Как должно быть** — ваш вариант.
4. **Ключ, если знаете** — в переводах ключ виден по имени файла и строке,
   например `chat.json` → `message.toolAdded`.

Не обязательно знать, где лежит строка: по тексту её легко найти поиском по
`locales/ru`.

## Исправить перевод самостоятельно

1. Найдите строку поиском:

   ```powershell
   Select-String -Path locales\ru\*.json -Pattern 'ваш текст'
   ```

2. Поправьте значение в соответствующем файле. **Ключ менять нельзя** —
   переводится только значение.
3. Пересоберите и проверьте:

   ```powershell
   node tools/build.js
   node tools/verify.js
   node tools/audit-bundle.js
   ```

4. Отправьте pull request. В описании достаточно одной строки: что и почему
   изменено.

### Обязательные правила

Проверяются автоматически в CI, поэтому лучше сразу:

| Правило | Почему |
|---|---|
| Файл = имя пространства имён | так устроен загрузчик: `chat.json` → `chat` |
| Набор и порядок ключей как в оригинале | иначе рассинхронизация с приложением |
| `{плейсхолдеры}` сохраняются дословно | `{count}` — подстановка во время показа |
| Многоточие — символ `…`, не три точки | единый вид интерфейса |
| Пустое значение остаётся пустым | некоторые строки задуманы пустыми |
| Только LF, без CRLF | проверяет аудит |
| Ничего личного: ни путей, ни имён, ни адресов | проверяет аудит |

## Добавить новый язык

Пакет написан под один язык, но механика переносится целиком:

1. Скопируйте `locales/ru` в `locales/<ваш-язык>`.
2. В `tools/build.js` поменяйте `LANGUAGE` на свой код и подпись, а также каталог
   источников.
3. Пересоберите: `node tools/build.js && node tools/verify.js`.

Если решите оформить это как отдельный репозиторий — ссылка на этот проект в
описании будет приятной, но не обязательной.

## Стиль перевода

Свод принятых терминов и правил — в [docs/glossary.md](docs/glossary.md).
Коротко: обычные слова интерфейса переводятся, а технические идентификаторы
(`JSON`, `API`, `MCP`, `PTC`), названия продуктов и служебные значения остаются
латиницей, чтобы интерфейс сходился с документацией.

Правки, меняющие термин во всём пакете, лучше оформлять отдельным pull request —
так видно область изменений.

## Чего делать не нужно

- **Не пересобирайте `lib/client.js` вручную** и не правьте его: он генерируется.
- **Не добавляйте зависимости**, `postinstall` и любые `scripts` в
  `package.json` — пакет намеренно их не имеет, это часть модели безопасности.
- **Не добавляйте сетевые вызовы** ни в бандл, ни в установщик: аудит это
  отклонит, и правильно сделает.
- **Не коммитьте личные данные**: скриншоты с реальными путями, названиями
  проектов и перепиской лучше обрезать или заменить.

## Проверки перед pull request

```powershell
node tools/build.js
git diff --exit-code lib/client.js   # артефакт совпадает с исходниками
node tools/verify.js
node tools/audit-bundle.js
```

Все четыре должны пройти. CI запускает ровно это.
