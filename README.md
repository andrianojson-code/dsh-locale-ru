**Русский язык для интерфейса DeepSeek Harness.** Полный перевод клиентской части:
58 пространств имён, 2615 строк.

Это не патч приложения. DeepSeek Harness изначально умеет подключать языковые
пакеты — здесь просто появляется язык `ru`, которого в поставке нет. Ничего не
скачивается, не требует прав администратора, не трогает файлы установки и
снимается одной командой.

```powershell
# установка (закройте приложение полностью: трей → Quit DeepSeek Harness)
powershell -ExecutionPolicy Bypass -File install-standalone.ps1
```

## Безопасность

Пакет распространяется как данные плюс один небольшой браузерный бандл. Это не
декларация, а проверяемое утверждение — в репозитории есть
[`tools/audit-bundle.js`](tools/audit-bundle.js), который механически проверяет
всё перечисленное ниже:

```powershell
node tools/audit-bundle.js
```

### Чего здесь нет

| Возможность | Проверяется |
|---|---|
| Сеть: `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon` | ✅ отсутствует |
| Исполнение кода из строки: `eval`, `new Function` | ✅ отсутствует |
| Локальное хранилище и cookie | ✅ отсутствует |
| Файловая система, процессы, переменные окружения | ✅ отсутствует |
| Electron, IPC, `require` системных модулей | ✅ отсутствует |
| Инъекция HTML: `innerHTML`, `createElement('script')` | ✅ отсутствует |
| Зависимости, `postinstall` и любые `scripts` в манифесте | ✅ отсутствуют |
| Телеметрия и обратные вызовы домой | ✅ отсутствует |

Серверная половина плагина — **367 байт** и представляет собой пустую функцию
без единого импорта: она существует только затем, чтобы пакет был обычной
строкой загрузчика. Вся содержательная работа — регистрация словарей.

### Что делает браузерная половина

Ровно три вызова, и никаких других обращений к контексту:

```js
ctx.effect(() => ctx.locale.addLanguage(LANGUAGE), '…: language');
ctx.effect(() => ctx.locale.register(ns, 'ru', DICTIONARIES[ns]), '…: ' + ns);
```

`LANGUAGE` — это `{ id: 'ru', label: 'Русский', fallback: 'en' }`. Словари —
обычные объекты «ключ → строка». Ничего не выполняется при установке: установщик
только копирует файлы.

### Установщик

- **Не требует прав администратора** и не запрашивает их. Всё происходит в папке
  текущего пользователя.
- **Ничего не скачивает** и не требует Node, pnpm или интернета.
- **Копирует только шесть файлов** из фиксированного списка
  (`package.json`, `cordis.patch.yml`, `lib/index.js`, `lib/client.js`), а не
  «всё, что лежит рядом».
- **Не трогает установку DeepSeek Harness** — ни одного файла в
  `Program Files`, `%LOCALAPPDATA%\Programs` и подобных местах.
- **Обратим**: [`tools/uninstall.ps1`](tools/uninstall.ps1) возвращает профиль к
  исходному состоянию, а `cordis.patch.yml` — побайтово к прежнему виду
  (проверено сравнением с копией до установки).
- **Ничего не запускает из интернета.** Все скрипты лежат в репозитории
  открытым текстом, их можно прочитать целиком перед запуском.

### Риски, о которых стоит знать

- **Скачанные `.ps1` блокируются Windows.** Если берёте файлы не из git, а
  архивом через сеть, снимите блокировку: правый клик по файлу → «Свойства» →
  «Разблокировать». Это защита Windows, и обходить её не нужно — просто снимите
  галочку осознанно.
- **Проверьте хеш** скачанного релиза, прежде чем запускать: см.
  [Проверка целостности](#проверка-целостности).
- **Пакет ставится в профиль, а не в систему.** Он не может повлиять на другие
  программы и не изменяет ядро приложения.

Порядок сообщения об уязвимости — в [SECURITY.md](SECURITY.md).

## Установка

### Требования

| | |
|---|---|
| ОС | Windows |
| Приложение | DeepSeek Harness для рабочего стола, **хотя бы раз запущенное** |
| Версия | `0.2.0-rc.2` (та же линейка; см. [Ограничения](#ограничения)) |
| Профиль | веб-типа — `desktop` или `web`; в консольном `tui` локали нет |
| Права | обычная учётная запись, **не администратор** |
| Node / pnpm / интернет | **не нужны** |

### Способ 1: один файл (рекомендуется)

1. Скачайте `install-standalone.ps1` из
   [последнего релиза](../../releases/latest) и положите куда угодно.
2. **Закройте приложение полностью** — правый клик по значку в области
   уведомлений → **«Quit DeepSeek Harness»**. Крестик в углу окна приложение не
   закрывает, а прячет в трей.
3. Откройте PowerShell в папке с файлом (Shift + правый клик по пустому месту →
   «Открыть окно PowerShell здесь») и выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File install-standalone.ps1
   ```

4. Запустите приложение. Язык подхватится сам; если нет —
   **Настройки → Общие → Язык → Русский**.

Установщик самодостаточен: весь пакет встроен внутрь, рядом ничего не нужно и
распаковывать нечего.

### Способ 2: из архива

```powershell
git clone https://github.com/andrianojson-code/dsh-locale-ru.git
cd dsh-locale-ru
powershell -ExecutionPolicy Bypass -File tools/install.ps1
```

### Нестандартный профиль

```powershell
powershell -ExecutionPolicy Bypass -File install-standalone.ps1 -ProfileDir "$env:USERPROFILE\.dsh\profiles\desktop"
```

Посмотреть доступные профили:

```powershell
Get-ChildItem "$env:USERPROFILE\.dsh\profiles" -Directory
```

Если задана переменная `DSH_HOME`, скрипты учитывают её автоматически.

## Что меняется в системе

Только внутри профиля `%USERPROFILE%\.dsh\profiles\desktop`:

| Путь | Что |
|---|---|
| `plugins\dsh-locale-ru\` | шесть файлов плагина |
| `node_modules\dsh-locale-ru\` | те же шесть файлов (загрузчик ищет имя пакета здесь) |
| `package.json` | `dsh-locale-ru` в `dependencies` и в `dsh.profile.bundles` |
| `cordis.patch.yml` | запись `- id: locale` с `preference: ru` |

Больше ничего. Бандлы самого приложения не патчатся, поэтому русификация
переживает обновления DeepSeek Harness и легко снимается.


Убирает пакет, его запись в манифесте и выбор языка. Приложение нужно так же
полностью перезапустить.

## Как это работает

1. `package.json` объявляет `dsh.bundle.patch` (слой профиля) и `dsh.client`
   (`platform: web`) — поэтому хост включает пакет и в серверное дерево, и в
   браузерный boot-граф страницы.
2. `cordis.patch.yml` добавляет одну строку загрузчика.
3. `lib/index.js` — пустая серверная половина, нужная только для этой строки.
4. `lib/client.js` — браузерная половина. Она вызывает
   `ctx.locale.addLanguage(...)` и по одному `ctx.locale.register(ns, 'ru', dict)`
   на каждое переведённое пространство имён.
5. Непереведённые ключи берутся из английского: у локали есть цепочка отката
   `ru → en`. Поэтому пакет можно наращивать постепенно и он никогда не
   показывает пустые строки.

Подробнее — в [docs/how-it-works.md](docs/how-it-works.md).

> **Перезапуск обязателен.** Хост читает браузерный бандл один раз при
> активации и обновляет его только через HMR-хук `rebuilt()`, а HMR у профиля
> запущен с `root: []` — исходники плагинов не отслеживаются. Обновление
> страницы (F5) не помогает, закрытие окна не завершает приложение.

## Проверка целостности

Сборка **воспроизводима**: одни и те же исходники дают побайтово одинаковый
бандл. Это позволяет проверить, что опубликованный артефакт соответствует
открытым исходникам:

```powershell
node tools/build.js
node tools/verify.js                      # контракт локали
node tools/audit-bundle.js                # аудит безопасности
git diff --exit-code lib/client.js        # бандл совпадает с исходниками
```

Текущий артефакт:

| Файл | Размер | SHA-256 |
|---|---|---|
| `lib/client.js` | 215 257 Б | `ab7b5414ad8d94f1a6ab212fca0fae1b85972736c7c6bf8022215a1243b80eb7` |
| `lib/index.js` | 367 Б | `0e6468313e04779e71d0a7defa4e370b14603ce9bd0631fdd7004d286e5a5c9c` |

## Ограничения

- **Каталог встроенных плагинов остаётся английским.** Названия и описания
  плагинов приложение берёт не из словарей, а из файлов
  `<пакет>/locale/<язык>.json`, поле `meta.description`. Чтобы файл подхватился,
  нужны два условия: он должен лежать **внутри самого пакета плагина** и пакет
  должен публиковать путь `"./locale/*.json"` в `exports`. Из 74 плагинов
  поставки это выполняют десять, и у всех есть только `en.json` и `zh.json` —
  русского нет. У остальных нет ни каталога `locale`, ни нужного `exports`.
  Поэтому и **в китайской локали там английский**: это поведение поставки, а не
  пробел перевода. Языковой пакет живёт в профиле и до файлов внутри архива
  приложения не достаёт — добавить их можно только правкой самого архива, а это
  противоречит устройству пакета и сломалось бы при первом обновлении. Всё
  остальное на странице — «Встроенные плагины», поиск, группировка, статусы,
  «Отключён» — переведено.
- **Версия приложения.** Пакет собран и проверен на `0.2.0-rc.2`. Он использует
  штатный сервис локализации; если в вашей версии он есть, всё заработает. На
  другой версии часть ключей может разойтись — это не поломка: отсутствующие
  строки покажутся по-английски.
- **Русские числовые формы.** Механизм локализации различает только `.one` и
  `.other`, а русскому нужны три категории. В `.other` используется родительный
  падеж множественного числа: «5 сообщений» верно, «2 сообщений» — нет. Это
  ограничение фреймворка, а не перевода.
- **Только веб-интерфейс.** В консольном профиле `tui` локали нет.
- **Только Windows.** Установочные скрипты написаны на PowerShell. Сам пакет
  платформо-независим, но установка на macOS и Linux потребует ручных шагов.

## Частые вопросы

<details>
<summary><b>Интерфейс остался английским</b></summary>

Почти всегда приложение не было закрыто по-настоящему. Закройте окно, затем
проверьте, висит ли значок в трее: если да — процесс жив, и новую версию он не
подхватит. Правый клик по значку → «Quit DeepSeek Harness», затем запуск заново.
F5 не помогает.
</details>

<details>
<summary><b>Приложение не запускается</b></summary>

Запустите `tools/uninstall.ps1` — профиль вернётся в исходное состояние.
</details>

<details>
<summary><b>PowerShell отказывается выполнять скрипт</b></summary>

Используйте `-ExecutionPolicy Bypass`, как в примерах. Это разовая мера для
одного запуска, системные настройки она не меняет.
</details>

<details>
<summary><b>Архив распаковался «плоско», без папок</b></summary>

Некоторые распаковщики теряют структуру. Возьмите `install-standalone.ps1` — ему
структура не нужна. Если нужно убрать оставшуюся россыпь:
`tools/cleanup-flat-extraction.ps1 -Folder <папка> -WhatIfOnly` покажет, что
будет удалено, и удалит только файлы, совпадающие с дистрибутивом по SHA-256.
</details>

<details>
<summary><b>Можно ли перенести на другой компьютер</b></summary>

Да — для этого и сделан `install-standalone.ps1`: один самодостаточный файл.
</details>

<details>
<summary><b>Переживёт ли русификация обновление приложения</b></summary>

Да. Пакет живёт в профиле, а не в папке установки, и обновление DeepSeek Harness
его не затрагивает. Исключение — если обновление пересоздаст профиль целиком.
</details>

## Разработка

```
locales/ru/<пространство>.json   переводы, по файлу на пространство имён
lib/index.js                     серверная половина (пустая, 367 Б)
lib/client.js                    СОБИРАЕТСЯ tools/build.js — не править вручную
tools/build.js                   сборка бандла из locales/
tools/verify.js                  проверка контракта локали
tools/audit-bundle.js            аудит безопасности
tools/install.ps1                установка из папки
tools/uninstall.ps1              удаление
tools/make-standalone.py         сборка установщика одним файлом
tools/make-banner.py             генерация баннера
```

Имя файла перевода = имя пространства имён DSH. Именно поэтому файлы с точкой
(`settings.locale.json`, `slash.menu.json`, `permission.access.json`) названы
так же, как пространства имён.

Цикл работы:

```powershell
node tools/build.js        # locales/ru/*.json -> lib/client.js
node tools/verify.js       # контракт: язык, пространства имён, ключи, плейсхолдеры
node tools/audit-bundle.js # запрещённые возможности, утечки, разметка
```

Как добавить язык или поправить строки — в [CONTRIBUTING.md](CONTRIBUTING.md).
