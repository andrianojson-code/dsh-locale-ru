# Как это устроено

Документ для тех, кто хочет понять механику, а не просто поставить пакет.

## Почему это плагин, а не патч

В DeepSeek Harness локализация — часть архитектуры. Пакет
`@deepseek-ai/dsh-client-locale` даёт сервис `locale`, в котором живут:

- реестр языков и словарей;
- выбор языка и его сохранение;
- сопоставление с языками браузера;
- цепочка отката при отсутствующем ключе;
- синхронизация атрибута `<html lang>`.

В поставке зарегистрированы два языка — `zh` и `en`. Всё остальное рассчитано на
подключение извне: язык можно добавить, не трогая ни одного файла приложения.
Этим и пользуется пакет.

Отсюда следуют практические свойства: установка не ломает подпись приложения,
переживает его обновление и снимается удалением шести файлов.

## Что происходит при установке

1. **Четыре файла** кладутся в профиль `%USERPROFILE%\.dsh\profiles\desktop`:
   в `plugins\dsh-locale-ru\` и в `node_modules\dsh-locale-ru\`.
   Вторая копия нужна потому, что загрузчик разрешает имя пакета обычным
   поиском по `node_modules`, а первая — это исходное место файлов.
2. **`package.json` профиля** получает запись в `dependencies` и в
   `dsh.profile.bundles`. Список бандлов — это порядок, в котором собирается
   дерево плагинов; наш пакет добавляется последним.
3. **`cordis.patch.yml` профиля** получает запись `- id: locale` с
   `preference: ru`. Это ровно то, что записала бы настройка
   «Настройки → Общие → Язык».

## Как пакет попадает в браузер

```
package.json  ──dsh.bundle.patch──▶  cordis.patch.yml  ──▶  строка загрузчика
                                              │
                                    ──dsh.client──▶  boot-граф window.__DSH_BOOT__
                                              │
                                    /plugins/dsh-locale-ru/client.js
                                              │
                                       window.__ModuleLoader__
                                              │
                                          apply(ctx)
```

- `dsh.bundle.patch` — серверная сторона: пакет становится слоем конфигурации.
- `dsh.client` с `platform: "web"` — браузерная сторона: хост добавляет пакет в
  boot-граф, и страница загружает один бандл.
- `exports["./client"]` указывает, какой файл отдавать по адресу
  `/plugins/<id>/client.js`.

## Что делает браузерный бандл

Файл `lib/client.js` — это саморегистрирующийся модуль. При загрузке он не
выполняет ничего, кроме регистрации фабрики; содержательная работа происходит,
когда модульную систему просят его материализовать.

```js
window.__ModuleLoader__.load({
  id: "dsh-locale-ru",
  factory: (require) => {
    var module = { exports: {} };
    var exports = module.exports;
    const LANGUAGE = { id: "ru", label: "Русский", fallback: "en" };
    const DICTIONARIES = { /* 58 пространств имён */ };
    function apply(ctx) {
      ctx.effect(() => ctx.locale.addLanguage(LANGUAGE), "dsh-locale-ru: language");
      for (const ns of Object.keys(DICTIONARIES)) {
        ctx.effect(() => ctx.locale.register(ns, "ru", DICTIONARIES[ns]), "dsh-locale-ru: " + ns);
      }
    }
    exports.apply = apply;
    exports.inject = ["locale"];
    return module.exports;
  }
});
```

- `inject: ["locale"]` — плагин активируется только после появления сервиса
  локализации.
- `ctx.effect(...)` — владение ресурсом: возвращённая функция-распорядитель
  отзывает регистрацию при выгрузке плагина.
- `fallback: "en"` — цепочка отката обязана заканчиваться на `en`, иначе
  регистрация отклоняется.

## Пространства имён и откат

Строки интерфейса разложены по пространствам имён — по одному на плагин
интерфейса. Имя файла в `locales/ru` совпадает с именем пространства, поэтому
файлы с точкой (`settings.locale.json`) названы так же, как пространства.

При показе строки происходит следующее:

1. ищется ключ в активном языке нужного пространства имён;
2. если нет — в следующем языке цепочки отката (`ru → en`);
3. если нет и там — та же цепочка повторяется в пространстве `common`;
4. если нет нигде — показывается сам ключ.

Поэтому неполный перевод безопасен: интерфейс никогда не показывает пустоту.

## Сборка

`tools/build.js` читает `locales/ru/*.json`, сортирует пространства имён и
подставляет словари в шаблон. Сборка **воспроизводима**: одни и те же исходники
дают побайтово одинаковый файл. Это не совпадение, а требование — на нём держится
проверка, что опубликованный бандл соответствует исходникам:

```powershell
node tools/build.js
git diff --exit-code lib/client.js
```

Если эта команда что-то показывает, артефакт и исходники разошлись, и такому
релизу доверять нельзя.

## Границы безопасности

Пакету не нужны ни сеть, ни файлы, ни хранилище: его задача — отдать
приложению статические словари. Все возможности, которых у него быть не должно,
перечислены и проверяются в `tools/audit-bundle.js`. Тот же скрипт следит за
тем, чтобы в репозиторий не попали абсолютные пути, адреса почты, токены и имя
пользователя.

Серверная половина — 367 байт пустой функции без импортов: она не выполняет
ничего и существует только для того, чтобы пакет был обычной строкой загрузчика.

## Ограничения механизма

- **Только две формы числа.** Локализация различает `.one` и `.other`, а
  русскому нужно три категории. В `.other` используется родительный падеж
  множественного числа: «5 сообщений» верно, «2 сообщений» — нет.
- **Текст, прочитанный при регистрации, не следует за сменой языка.** Строки,
  захваченные вне отрисовки, сохраняют язык, под которым были зарегистрированы,
  до повторной регистрации.
- **Нет правил множественного числа и двунаправленной вёрстки.** Реестр даёт
  выбор языка, сохранение, сопоставление с браузером, откат по ключам и
  `<html lang>` — и только это.
