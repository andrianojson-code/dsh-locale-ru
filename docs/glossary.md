# Глоссарий перевода DSH → русский

Итоговое правило: **переводится всё, что является обычным словом интерфейса**;
латиницей остаются только технические идентификаторы, названия продуктов и
значения-данные. Это даёт цельный русский интерфейс; при этом любой термин можно
вернуть в латиницу одной правкой.

## Остаётся латиницей

| Что | Примеры |
|---|---|
| Технические аббревиатуры | JSON, DSH, API, CLI, MCP, PTC, HTTP, URL, ID, SSE, EXP |
| Названия продуктов и моделей | DeepSeek, GPT, GitHub |
| Имена файлов, пути, расширения | `.docx`, `README.md`, `dsh web` |
| Идентификаторы и значения-данные | `compact`, `read-only`, `api-key` |
| Клавиши | Enter, Esc, Tab, Ctrl |
| Токены-команды слэша | `/compact`, `/permission` |

## Обязательные правила формата

1. **Ключи JSON не менять** — переводятся только значения.
2. **Плейсхолдеры сохранять дословно**: `{name}`, `{count}`, `{toolName}`, `{value}`,
   `{total}`, `{action}`, `{label}`, `{title}`, `{duration}` и любые другие `{...}`.
3. Экранированные последовательности (`\n`, `\"`) сохранять как есть.
4. Многоточие — символ `…` (не три точки), как в оригинале.
5. Тон: нейтральный, краткий, как в оригинале. Не добавлять пояснений.
6. Не переводить текст внутри обратных кавычек и код-подобные фрагменты.
7. Вывод — **валидный JSON, UTF-8, те же ключи, без комментариев**.

## Известное ограничение

Русские числовые формы (1 сообщение / 2 сообщения / 5 сообщений) требуют трёх
категорий, а механизм локализации DSH различает только `.one` и `.other`.
В `.other` используется родительный падеж множественного числа
(`{count} сообщений`) — он верен для большинства чисел, но для 2–4 читается
неточно. Это ограничение фреймворка, а не перевода.
