# Как опубликовать репозиторий

Пошаговая инструкция для владельца. Выполняется один раз.

## 0. Что понадобится

- **Git** — поставьте [Git for Windows](https://git-scm.com/download/win), если
  его ещё нет, либо используйте GitHub Desktop.
- Аккаунт GitHub.

## 1. Проверьте логин в ссылках

В ссылках уже подставлен логин `andrianojson-code`. Если он не совпадает с вашим:

```powershell
python tools/set-owner.py --login ваш-логин
git add -A
git commit --amend --no-edit
```

Скрипт заменит логин во всех ссылках разом и проверит, что он вообще допустим
на GitHub. Посмотреть, где логин упоминается сейчас:

```powershell
git grep -n "andrianojson-code" -- "*.md" "*.yml"
```

## 2. Замените имя правообладателя (по желанию)

В `LICENSE` стоит `dsh-locale-ru contributors`. Если хотите указать своё имя —
поменяйте; для MIT это не обязательно.

## 3. Проверьте, что в репозитории нет личного

Аудит делает это сам, но полезно знать, что именно он ищет:

```powershell
node tools/audit-bundle.js
```

Он падает, если найдёт абсолютные пути (`C:\Users\...`), адреса электронной
почты, токены, ключи AWS, приватные ключи или имя пользователя этой машины.
Заодно проверяет, что нигде нет CRLF.

Отдельно стоит глазами пройтись по будущим скриншотам: на них не должно быть
названий ваших проектов, путей и переписки.

## 4. Проверьте, что в коммит попало только нужное

Репозиторий уже инициализирован, первый коммит сделан. Убедитесь, что в него не
просочилось лишнее:

```powershell
git ls-files | Measure-Object -Line          # ~88 файлов
git ls-files | Select-String 'dist/|\.zip$'  # должно быть пусто
git status --short                           # должно быть пусто
```

`dist/` с релизными архивами и `node_modules/` в репозиторий не попадают — они
в `.gitignore`. Бандл `lib/client.js` попадает намеренно: он публикуется как
проверяемый артефакт, и CI сверяет его с исходниками.

## 5. Создайте репозиторий на GitHub

Через веб-интерфейс: **New repository** →

- имя: `dsh-locale-ru`;
- **не** добавляйте README, .gitignore и лицензию — они уже есть;
- видимость: Public.

Затем свяжите локальный репозиторий с удалённым и отправьте:

```powershell
git remote add origin https://github.com/andrianojson-code/dsh-locale-ru.git
git push -u origin main
```

При первом push Git спросит учётные данные — откроется окно входа GitHub.
Это нормально и происходит только один раз.

## 6. Настройте репозиторий

- **About** → короткое описание и темы: `deepseek-harness`, `localization`,
  `russian`, `i18n`, `translation`, `windows`.
- **Security** → включите **Private vulnerability reporting** (нужно для
  `SECURITY.md`).
- **Actions** → вкладка должна показать зелёный прогон `verify` после первого
  push. Если он красный — смотрите лог, скорее всего разошёлся `lib/client.js`.

## 7. Соберите релиз

```powershell
python tools/make-release.py --version 1.0.0
```

Скрипт соберёт в `dist/`:

- `install-standalone.ps1` — установщик одним файлом;
- `dsh-locale-ru-1.0.0.zip` — пакет с исходниками;
- `SHA256SUMS` — контрольные суммы.

Затем на GitHub: **Releases → Draft a new release** →

- tag: `v1.0.0`;
- заголовок: `1.0.0 — полный перевод`;
- описание: возьмите раздел из `CHANGELOG.md`;
- приложите три файла из `dist/`.

## 8. Что проверить после публикации

- [ ] CI зелёный на `main`.
- [ ] Бейджи в README отображаются (лицензия, покрытие, аудит).
- [ ] Баннер `assets/banner.png` виден в шапке.
- [ ] В релизе лежит `SHA256SUMS`, суммы совпадают с файлами.
- [ ] Приватные сообщения об уязвимости включены.
- [ ] Скачали релиз на чистую машину и поставили по инструкции из README.

## Обновление перевода после публикации

```powershell
node tools/build.js
node tools/verify.js
node tools/audit-bundle.js
git add -A
git commit -m "перевод: уточнения в <раздел>"
git push
```

Если менялся бандл — поднимите версию в `CHANGELOG.md` и соберите новый релиз.
Установщик одним файлом привязан к версии бандла, поэтому старые релизы после
обновления исходников становятся неактуальными: это нормально.
